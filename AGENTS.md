The selected object path commits booking/revision/idempotency and destination-bound outbox changes atomically under generation-conditional writes; the optional SQL path retains database constraints. Preserve old reservations on failed reschedules and workspace-scoped authorization.

In object mode, one authenticated Scheduler-driven worker delivers; optional SQL retains Tasks. The outbox and account/connection/workspace-scoped mappings support retries/recovery. Repeated delivery, late revisions, expiry, destination changes and ambiguous external creates must be safe and honest.
- Visitor HubSpot access/refresh tokens and the app client secret stay in protected server-side storage. A separate operator-controlled test account may use a supported static token in server-only ignored `.env.local` locally or Google Secret Manager on deployment for specifically authorized acceptance; it is never a fallback for a skipped/denied/failed visitor connection. No public CRM proxy, shared operator login or app-sent email/SMS outreach. HubSpot's own admin uninstall notification must be disclosed; it is not an app-sent campaign. Touch only explicitly created demo records. Verify account scopes, upsert/uniqueness and cleanup support; revocation can prevent cleanup and must be reported honestly.
- Keep a small provider/tool vocabulary. Model output cannot run SQL, arbitrary HTTP, shell commands, confirm prices or invent successful actions.
- Pydantic/OpenAPI own API schemas; generate narrow browser types rather than hand-maintaining divergent business contracts. Keep the Python domain independent of FastAPI/vendor startup.
